# Repository layout

Git remote: `origin` = `git@github.com:charles-cyluo/16709-efficient-reorient.git` (branch `main`).

```
src/reorient/
  __init__.py            ASSETS_DIR, SCENE_XML, TABLE_Z
  assets/
    scene.xml            floor, table, includes cup.xml + the vendored Panda (stock hand); keyframe "ready"
    scene_robotiq.xml    same scene with the arm only (panda/panda_nohand.xml); table edge 4.5 cm further back;
                         the Robotiq 2F-85 is attached in Python (envs/model.py); no keyframe (ready pose by IK)
    scene_widowx.xml     table + cup scene for the WidowX 250 S (arm attached in Python: envs/model.py build_widowx_model)
    wx250s/              vendored Menagerie trossen_wx250s MJCF + meshes (unmodified)
    cup.xml              hollow cup + a thin solid cylinder variant (generated by scripts/make_cup_xml.py)
    panda/               vendored Panda MJCF + meshes (see "Assets" below)
    robotiq_2f85/        vendored Robotiq 2F-85 MJCF + meshes (see "Assets" below)
  envs/model.py          build_model(gripper): stock Panda hand, or Robotiq 2F-85 attached with MjSpec
  envs/panda_cup_env.py  PandaCupEnv(gripper="panda"|"robotiq") (Gymnasium-style): randomized cup, joint-target actions
  envs/widowx_sim.py     WidowX + thin cylinder simulation helper (model, IK, scene configuration; shared by controllers, metrics, RL env)
  envs/widowx_flip_env.py WidowXFlipEnv: RL environment (episode from the pickup state, task + efficiency reward terms), see implementations/widowx-flip-env.md
  policies/
    cartesian.py         damped-least-squares Cartesian controller, offline solve_ik, R_SIDE (side-grasp TCP frame)
    rigid_flip.py        scripted rigid flip baseline (side grasp, wrist roll, place inverted)
    pivot.py             exploratory scripted pivot + set-down on the stock Panda hand (does not work, see the pivot note, Part 6)
    widowx_expert.py     scripted wrist roll acting through the WidowXFlipEnv action interface
  eval/
    metrics.py           EpisodeMetrics: success, drop, completion time, arm-link travel, wrist rotation, gravity-assist ratio (docs/project/metrics.md)
    aggregate.py         aggregate per-episode metrics (success rate with Wilson CI, means) and format the comparison table
scripts/
  run_rigid_flip.py      N randomized trials (--gripper panda|robotiq), optional mp4 of trial 0
  make_cup_xml.py        regenerate assets/cup.xml
  probe_pivot.py         exploratory pivot probe (not a baseline): pinch low, lift, reduce grip, optional video
  run_pivot.py           scripted pivot + set-down baseline runner (stock hand, thin cylinder; currently ~0% success)
  run_width_pivot.py     width-controlled pivot + placement on the WidowX (IK + finger width control; experiment, see experiments note Part 12)
  search_width_pivot.py  random search / validation of the width-pivot parameters over (mass, COM height) scenes, one subprocess per scene
  sweep_width_pivot.py   parallel (multiprocessing) sweeps of the width pivot over mass / release width / closing squeeze / trigger; results to outputs/sweeps/ (git-ignored)
  eval_baselines.py      scripted pivot / roll over random scenes with the metrics (parallel subprocesses)
  train_ppo.py           PPO (SB3) on WidowXFlipEnv, task-only or task + efficiency reward; run dir outputs/runs/<date>-<name>-<seed>
  eval_policy.py         trained policies over random scenes + comparison table with the scripted baselines
  render_policy.py       video of a trained policy rollout
  probe_widowx.py        same probe with the WidowX 250 S on the table (standalone sim, not wired into the env)
tests/                   light tests (env steps, rigid flip inverts the cup, WidowX env incl. learn_grasp mode)
docs/                    project / sessions / experiments / implementations
```

## Assets

- **Panda**: copied from [MuJoCo Menagerie](https://github.com/google-deepmind/mujoco_menagerie)
  `franka_emika_panda/`, commit `370c43965323c0944b433b202aac5058b5f907a9` (Apache-2.0,
  license kept in `assets/panda/LICENSE`). ~33 MB, mostly visual `.obj` meshes.
- Local patches to `panda/panda.xml` (all marked `REORIENT PATCH`):
  1. `meshdir` changed to `panda/assets` (resolved relative to `scene.xml`).
  2. Collision geoms: `condim=4`, `friction=1.5 0.02 0.001` (grippier pads).
  3. Added site `tcp` at `0 0 0.1034` in the `hand` body (between fingertip pads).
  4. Gripper actuator `kp` 100 -> 1000 (stock gripper only gives ~3 N, can't hold a cup),
     tendon forcerange ±140 N.
- Menagerie's `hand.xml` was not copied (unused: the arm file already contains the hand).
- **Robotiq 2F-85**: copied from MuJoCo Menagerie `robotiq_2f85/` (same commit `370c439...`, license in
  `assets/robotiq_2f85/LICENSE`, 3 MB), unmodified. `assets/panda/panda_nohand.xml` (same commit) is the arm without
  a hand; only `meshdir` was changed to `panda/assets`. `envs/model.py` attaches the gripper to the arm's
  `attachment` body and adds a `tcp` site at the pad centre (14.15 cm from the flange) rotated so the TCP frame has
  y = finger-opening axis, z = approach (same convention as the stock hand).
- **WidowX 250 S** (experiment only): copied from MuJoCo Menagerie `trossen_wx250s/` (same commit `370c439...`,
  license in `assets/wx250s/LICENSE`), unmodified (the unused AR-tag mesh was dropped). `assets/scene_widowx.xml`
  is the table + cup scene; `envs/model.py:build_widowx_model()` attaches the arm at the table top (x = 0.2 m) and adds
  a `tcp` site between the finger contact spheres. Not used by `PandaCupEnv`.
